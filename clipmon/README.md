# Kimi ClipMon — Windows 截图目录监视（引用版）

为 **Kimi CLI** 打造的轻量截图自动编号工具。

**核心设计**：守护进程通过监视文件夹自动为截图分配编号 `@N`。同时内置**剪贴板桥接**，自动读取剪贴板中的截图并保存到 inbox，**只读不写，不影响任何其他软件的正常复制粘贴**。

---

## 快速开始

### 1. 环境要求
- Windows 10/11
- Python 3.8+（需已安装 **Pillow**）

### 2. 启动守护进程

**方式 A：直接双击启动（推荐）**
```powershell
cd clipmon
.\start.ps1
```
运行后 PowerShell 窗口会自动隐藏，系统托盘出现图标。拖到任务栏常驻区。

**方式 B：终端手动启动（调试用）**
```powershell
python daemon.py
```

### 3. 验证是否工作

**方式 A（任意截图工具）：**
1. 按 `Win+Shift+S` 或微信 `Alt+A` 截图
2. 截图进入剪贴板（微信点「完成」，系统截图直接完成）
3. 右下角托盘弹出气泡：`Saved @3`
4. **点击气泡** → `@3` 复制到剪贴板
5. 在 Kimi CLI 中 `Ctrl+V` 粘贴 `@3`

**方式 B（手动放入 inbox）：**
1. 把图片文件拖入 `~/.kimi-cli/clips/inbox/`
2. 托盘弹出气泡，点击即可复制编号

## 使用流程（重点）

### 单张图（任意截图工具通用）
```
你截图（Win+Shift+S / 微信 Alt+A / QQ / Snipaste）
    ↓
图片进入剪贴板
    ↓
剪贴板桥接自动保存到 inbox
    ↓
守护进程分配编号，如 @3
    ↓
右下角托盘气泡弹出：Saved @3（点击复制）
    ↓
你回到 Kimi CLI，粘贴 @3：

    这里报错是什么意思 @3

    ↓
我看到 @3，自动读取对应图片分析
```

### 多张图连续截
```
截图 A → 剪贴板 → 编号 @1
截图 B → 剪贴板 → 编号 @2
截图 C → 剪贴板 → 编号 @3
```

需要引用 `@1` 或 `@2` 时：
- **点击气泡** → 已复制的编号可以粘贴
- **左键单击托盘图标** → 打开 `latest.md`，查看全部编号

### 在 Kimi CLI 中的对话示例

```
你: 这个报错是什么意思 @3
我:  这是 ModuleNotFoundError，说明...

你: 对比下 @1 和 @2 的配置差异
我:  好的，@1 里数据库 host 是 localhost，@2 里改成了 192.168...

你: 先 @1 是正常状态，@3 是报错，帮我排查
我:  从 @1 到 @3，变化在于...
```

**完全不需要你手动输入路径或文件名**，记住 `@N` 即可。

## 目录结构

```
C:\Users\<用户名>\.kimi-cli\clips\
├── inbox\                        # 监视目录：放入此处的图片会被自动处理
├── 20260501_185030_123.png      # 自动保存的截图
├── 20260501_185045_456.png
├── manifest.jsonl               # 元数据（含编号、路径、时间）
├── latest.md                    # 最近 30 张索引（含编号）
├── .notify                      # 通知触发文件（内部使用）
└── daemon.log                   # 守护进程日志
```

## 托盘菜单说明

| 菜单项 | 功能 |
|--------|------|
| Recent tags (&H) | 查看最近 5 张的 `@N` 列表（只读显示） |
| Open clips folder (&O) | 用资源管理器打开 clips 目录 |
| View latest list (&L) | 用记事本打开 `latest.md`，看全部编号 |
| Cleanup old clips (&D) | 手动触发清理过期截图 |
| 退出 | 关闭守护进程 |

左键单击托盘图标：直接打开 `latest.md`。

## 编号规则

- **全局递增**：`@1`, `@2`, `@3`... 基于 `manifest.jsonl` 历史总条数，守护进程重启不会重置
- **唯一性**：同一次会话内不会重复，跨会话也连续
- **简洁性**：`@N` 只有 3~5 个字符，嵌入自然语言句子毫无违和感

## 常见问题

**Q: 需要手动把截图放进 inbox 吗？**  
A: **不需要**。守护进程自带剪贴板桥接，系统截图、微信截图、QQ 截图等只要图片进了剪贴板，会自动保存到 inbox。你也可以手动拖放图片进去。

**Q: 连续放了 3 张图，怎么引用第一张？**  
A: 左键单击托盘图标打开 `latest.md`，查看全部编号列表。

**Q: 编号会冲突吗？**  
A: 不会。编号基于持久化的 `manifest.jsonl` 递增，除非手动删除该文件。

**Q: 怎么彻底关闭？**  
A: 右键托盘图标 → Exit。异常残留时在任务管理器结束 `python.exe` 或 `powershell.exe`。

## 原理简述

```
你截图 (Win+Shift+S / 微信 / QQ / Snipaste)
    ↓
图片进入系统剪贴板
    ↓
剪贴板桥接线程 (2.5 秒轮询) 读取并保存到 inbox
    ↓
目录监视线程 (1 秒轮询) 检测到新文件
    ↓
保存为 ~/.kimi-cli/clips/YYYYMMDD_HHMMSS_ms.png
    ↓
生成全局递增编号 @N
    ↓
托盘气泡弹出：Saved @N（点击复制到剪贴板）
    ↓
你在 Kimi CLI 中自由描述 + @N → 我读取对应图片
```

**关键特性：只读取剪贴板，绝不修改**。你的复制粘贴行为完全不受影响。
